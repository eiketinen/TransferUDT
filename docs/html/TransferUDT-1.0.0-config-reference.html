Referencia parametro por parametro

Este documento explica os parametros de configuracao do cliente Agent e do Server do TransferUDT. A referencia foi alinhada aos arquivos AgentUDTC++_v7.2/config.example.properties, ServerUDTC++_v3/config.example.properties e aos loaders de configuracao usados em tempo de execucao.

ClienteRadarAgentUDTService
ServidorServerUDTService
Formatoproperties key=value
SegurancaPSK ou signed_handshake

Visao geral

O TransferUDT usa dois arquivos principais de configuracao:

  • Agent: define para onde enviar arquivos, quais pastas observar, politicas de chunk, retry, logs, banco local, seguranca e Dashboard.
  • Server: define porta de escuta, limites, diretorios de armazenamento/reconstrucao, filas de trabalho, logs, banco, politicas de cliente e seguranca.
Regra pratica: em producao, copie os arquivos config.example.properties para config.properties, ajuste caminhos locais, IDs de cliente e segredos, e nunca publique arquivos com PSK, chaves privadas, certificados ou caminhos internos reais.

Seguranca

Nunca use o placeholder em producao. Qualquer PSK real deve ter no minimo 32 caracteres, deve ser diferente por ambiente e nao deve ser versionada.

Operacao

  • Depois de alterar config.properties, reinicie o servico correspondente.
  • Para Agent, valide server.targets, data.dirs, security.client_id e PSK/chaves antes de iniciar.
  • Para Server, valide server.allowed_clients, security.allowed_client_ids, limites de tamanho e caminhos de disco.
  • Se um arquivo for alterado no mesmo caminho monitorado e resend.changed_files.enabled=true, o Agent detecta novo conteudo por SHA-256 e reenvia; o Server aplica resend.changed_files.server_policy.
  • A estrutura de subpastas dentro da pasta monitorada e preservada no destino reconstruido do Server.

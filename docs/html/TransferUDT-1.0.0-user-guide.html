TransferUDT 1.0.0

Sistema Windows para transferencia de arquivos por UDT com Agent, Server, Dashboard HTTPS, servicos Windows, seguranca por handshake e pacote oficial de distribuicao.

PlataformaWindows x64
InstalacaoWizard administrativo
DashboardHTTPS 8443
ServerTCP 50051

Visao geral

TransferUDT move arquivos entre maquinas Windows em rede privada ou controlada. O Agent observa diretorios locais, divide arquivos em chunks e envia para o Server. O Server valida, persiste e reconstrui os arquivos. O Dashboard oferece observabilidade via HTTPS.

Agent

Monitora pastas, detecta estabilidade do arquivo, envia chunks, registra estado local e reporta heartbeat ao Dashboard.

Server

Recebe chunks, valida limites, hash e politica de cliente, armazena partes e reconstrui o arquivo no destino.

Dashboard

Mostra Agents online, falhas, transferencias, status do Server e logs recentes em uma interface HTTPS local.

Arquitetura

1. WatchArquivo aparece na pasta monitorada do Agent.
2. ChunkAgent divide o arquivo e calcula metadata/hash.
3. TransferChunks sao enviados ao Server por UDT.
4. RebuildServer grava chunks e reconstrui o arquivo.
5. ObserveDashboard exibe status, logs e heartbeats.

Pre-requisitos

Maquina de execucao

  • Windows 10/11 ou Windows Server x64.
  • Usuario administrador para instalar servicos.
  • Porta TCP do Server liberada entre Agent e Server: 50051.
  • Porta HTTPS do Dashboard liberada para operadores: 8443.
  • Certificado .pfx para Dashboard em producao.

Maquina de build

  • Visual Studio 2022 com workload C++ Desktop.
  • .NET SDK 8.
  • Inno Setup 6.
  • Dependencias C++ via vcpkg.

Instalacao pelo wizard

  1. Execute TransferUDT-1.0.0-windows-x64-setup.exe como administrador.
  2. Escolha o perfil: Agent, Server, Server+Dashboard ou completo.
  3. Preencha os campos solicitados pelo wizard.
  4. Mantenha marcada a opcao de iniciar servicos apos instalar.
  5. Valide os servicos e o Dashboard.
Producao: substitua certificados e segredos de teste por material criptografico controlado pela organizacao.

Identidade X.509 de alta garantia

Quando houver PKI interna, use certificate_handshake nos dois peers. O Agent valida CA, EKU serverAuth e SAN/CN do Server; o Server valida CA, EKU clientAuth, SAN/CN e allowlist do Agent. Configure os caminhos de chave privada, certificado PEM e CA descritos na referencia. Esse perfil protege o handshake do protocolo UDT, mas nao e transporte TLS/mTLS. Para revogacao local, configure security.revocation.mode=crl e o bundle indicado por security.crl_path. O material criptografico e recarregado em novos handshakes, permitindo rollover com CAs sobrepostas sem encerrar transferencias ativas. Download de CRL, OCSP e renovacao automatica continuam externos.

Dashboard

Abra o Dashboard em https://localhost:8443/ ou no host configurado. Use a senha de operador criada no wizard.

IndicadorSignificadoAcao esperada
Agents onlineAgents com heartbeat recente.Confirmar que todos os hosts esperados aparecem.
Agents offlineAgents conhecidos sem heartbeat recente.Verificar servico, rede e URL do Dashboard no Agent.
Arquivos pendentesCaminhos distintos aguardando envio ou finalizacao; varios chunks do mesmo arquivo contam uma vez.Monitorar se a fila diminui.
Arquivos processadosArquivos persistidos pelo Agent como concluidos.Comparar conclusoes com o volume esperado.
FalhasErros reportados por Agent ou Server.Ler logs e corrigir causa raiz.
Saude dos componentesReadiness do banco do Dashboard, banco/log do Server e heartbeats.Investigar componentes degraded ou unhealthy.
Concluidas e erros na janelaEventos persistidos pelo Server em 6 horas a 7 dias.Comparar volume concluido, falhas e backlog.
Tendencia de backlogFila e falhas reportadas por bucket de heartbeat.Verificar se a fila reduz depois da recuperacao.
Alertas ativosAgent offline, servico parado, falhas ou disco baixo.Tratar primeiro os alertas de erro.

/health/live pode ser usado por probes sem login. Os endpoints detalhados /api/health e /api/metrics exigem sessao autenticada do operador.

Os contadores do Agent representam arquivos, nao chunks, e sao lidos em um unico retrato consistente do banco local. O campo lastTransferAt informa em UTC a ultima conclusao persistida ou permanece nulo antes da primeira transferencia bem-sucedida.

Retomada apos interrupcao

O Agent mantem no banco local os chunks pendentes, offsets e o identificador da transferencia. Depois de uma parada inesperada, o servico retoma o envio; chunks que o Server ja armazenou sao reconhecidos de forma idempotente e nao alteram os contadores.

  • Nao apague o banco local do Agent durante uma recuperacao.
  • Confirme nos logs o reenvio de chunks pendentes e a conclusao do arquivo.
  • Valide o SHA-256 do arquivo reconstruido antes de liberar o conteudo.

Troubleshooting

Dashboard mostra tudo zero
  • Confirme login e clique em Atualizar.
  • Confirme dashboard.enabled=true no Agent.
  • Confirme dashboard.url=https://host:8443.
  • Leia agent.log para HTTP 400/401.
Agent nao conecta ao Server
  • Teste porta 50051 a partir do Agent.
  • Valide server.targets.
  • Valide server.allowed_clients.
  • Compare security.client_id e PSK entre Agent e Server.
Arquivo nao e reconstruido
  • Confira se o arquivo ainda esta sendo escrito no Agent.
  • Leia server.log para rejeicao de hash, nome, tamanho, quota ou politica resend.changed_files.server_policy.
  • Confira storage e reconstructed no Server.
Erro no instalador de servicos
  • Execute como administrador.
  • Confirme se servicos antigos foram parados.
  • Confirme PFX e senha do PFX.
  • Em laboratorio limpo, marque substituicao de configuracoes.
